# ADR-002: ZIP method 95/XZ is a verification gate, not a promised feature

**Status:** blocking spike. Apache Commons Compress `ZipMethod.XZ(95)` is a named method enum, not a decoder. `ZipFile.getRawInputStream` returns raw compressed member bytes. XZ for Java 1.12 `SingleXZInputStream(in, memoryLimitKiB, true)` can decode valid XZ streams with memory cap and validation; **nothing reviewed proves authentic ZIP95 entry data exactly equals a standard single XZ stream**. Commons `getInputStream` cannot be used directly for method95; wrapping it is wrong.

**Evidence required before shipping:** complete authentic method95 fixture made by independent producing implementation; central AND local headers method95 verified, GPBF and descriptor parsing, ZIP64 field handling, compressed and uncompressed length, source ground-truth file hash, XZ stream/footer and ZIP CRC; malicious/truncated/encrypted/incorrect-size/duplicate/path-traversal/expansion tests; pre/post limits and no host crash. At least two independent decoders/tool outputs if available. Observe actual previously unreadable plugin only after explicit user permission and original bytes obtainable. If no valid fixture: report `UNSUPPORTED_ZIP_METHOD_95` and keep coverage PARTIAL.

**Dependencies:** Apache Commons Compress: candidate Java8, Apache-2.0, pure Java, ZIP index useful; verify 1.28.0 jar graph and advisories. XZ for Java: prefer >=1.12 review (official 1.12 fixes significant 1.10/1.11 issue), 0BSD since 1.10, Java8. Neither approved for shipping without actual Java8/D8 API24 validation. No JNI requirement. D8 method count and memory impact must be measured.
