## Assertions adjudicated by primary specification

- **Apache ZIP95:** `ZipMethod.XZ = 95` is *identifier recognition only*. Apache ZIP documentation lists which methods are decompressed and excludes XZ; `ZipFile.getRawInputStream(ZipArchiveEntry)` returns raw compressed bytes, not the uncompressed member. XZ for Java `SingleXZInputStream(InputStream,int,boolean)` exists and its `memoryLimit` is **KiB**, `verifyCheck=true` validates XZ integrity, but *ZIP95 payload framing and independent CRC validation still require an authentic sample*. Never wrap `ZipFile.getInputStream()` with an XZ decoder. Sources: https://commons.apache.org/proper/commons-compress/zip ; https://commons.apache.org/proper/commons-compress/apidocs/org/apache/commons/compress/archivers/zip/ZipFile.html ; https://tukaani.org/xz/xz-javadoc/org/tukaani/xz/SingleXZInputStream.html ; https://support.pkware.com/pkzip/appnote .
- **Host SDK:** Official MT v3 getting-started guide explains SDK v3 preference entry and packaging via its **demo Gradle project**; that does *not* mean this repository uses Gradle. Source https://mt.cc/guide/plugin-v3/getting-started.html . `mainPreference` must implement host preference contract and `dexMode` packaging must be tested in MT Manager; compile-only host API cannot be repackaged blindly.
- **Signature syntax:** `.ndb` extended signature grammar is `name:TargetType:Offset:HexSignature[:min_flevel[:max_flevel]]`; target and offset semantics matter. Some ClamAV features require FLEVEL gating; matcher subsets are not equivalent to engine support. Sources https://docs.clamav.net/manual/Signatures.html ; https://docs.clamav.net/manual/Signatures/ExtendedSignatures.html ; https://docs.clamav.net/manual/Signatures/BodySignatureFormat.html .
- **Supply chain:** File checksum obtained alongside a mutable download is integrity checking, **not publisher authentication**. Signed release manifests require pinned verification keys and rotation process. OSV advisories alone do not prove exploitability. https://osv.dev/docs/ .
